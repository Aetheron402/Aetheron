Aetheron Roadmap

Where Aetheron goes from here, through the end of 2027. Everything already shipped lives in the product, not on this page: what follows is what is being built next and what it unlocks.

Q3 2026: Relaunch and Token (July-September) (in progress)

  • Done $AETH Token Launch: Released on Pump.fun. AETH payments activate across every component the moment the mint exists, with no redeploy and no code change.
  • Done Open Source Release: The entire platform in one public repository, payment verification included, so nothing about how you are charged is hidden.
  • Done AETH Fee Tier: Paying in AETH costs less than paying in USDC, applied at the protocol layer rather than as a promotion.
  • Done AETH Burn on Use: AETH taken as payment is burned rather than kept. Burns are made in batches and every one is a public transaction, listed on the token page against a running count of what has come in and what has gone out, so the figure can be checked rather than believed.
  • Component Usage Feed: A live public record of what is being bought and run, tied to on chain settlement. Live now.

Q4 2026: Agents That Buy, and Agents You Sell (October-December)

  • MCP Server: Every component exposed over the Model Context Protocol, so an assistant can call Aetheron directly and settle the payment itself without a human in the loop.
  • Hosted Agent Runs: The monitoring agents run on our infrastructure and bill per run through X402, for the agents that need no keys of yours.
  • Aetheron CLI: Bulk prompt and code analysis from a terminal, with the payment handshake handled and results streamed to stdout.
  • EVM Settlement: Pay from an EVM wallet, not just connect one. MetaMask, Base and Arbitrum routed to the same component layer.
  • Community Agents: Publish an agent template to the store and be paid per sale, with the buyer's payment settling straight to your wallet and the protocol cut taken at settlement rather than invoiced. Every submission is reviewed before it is listed, because these are projects people run against their own keys.
  • Agent Wallets: Give an agent a spending limit and let it buy components on its own inside that budget.

Q1 2027: Composition (January-March)

  • X402-Linker: Chain components so one output feeds the next, settled per hop, with no central API sitting in the middle taking a cut.
  • Orchestration Canvas: Build those chains visually. Optimise, then analyse, then test, as one run with one receipt.
  • Local Node Runtime: Execute Aetheron tasks on your own machine against your own keys, for work that must never leave it.
  • Component Versioning: Pin a component to a version so a workflow you built keeps returning what it returned when you built it.
  • Conditional Routing: Branch a chain on what a component returned, so a risk score above a threshold triggers a different path.

Q2 2027: Verification and Trust (April-June)

  • Aetheron Trust Ledger: Every generated report certified on chain by transaction hash, so its origin and its contents can be proven later.
  • Output Verification: Paste a report or a hash and confirm it came from Aetheron, unmodified, at the time it claims.
  • Decentralised Storage: Report archives on IPFS and Arweave with content proofs, so delivery does not depend on us staying online.
  • Transparency Dashboard: Live transaction flow, component usage and revenue, readable by anyone without asking us.
  • Reproducible Runs: Re-run any past report against its original inputs and confirm you get the same answer.

Q3 2027: An Open Marketplace (July-September)

  • Community Components: The second half of what opened to agent authors in Q4 2026. Publish a component that runs on our infrastructure, not just a project to download, sandboxed and metered, and be paid per call.
  • Creator Revenue Sharing: A smart contract splits every payment between the component author and the protocol at settlement.
  • Public API Registry: Every endpoint, its version, its price and its usage, searchable and callable by anything that speaks X402.
  • Component Reputation: Ranking built from settled usage and verified outputs, not from stars anyone can buy.
  • Multi-Chain Components: The same component callable and payable across Solana, Base and Arbitrum.

Q4 2027: Autonomy and Governance (October-December)

  • Agent to Agent Commerce: Agents discover, hire and pay other agents through the registry, with every hop settled and auditable.
  • Autonomous Treasuries: An agent holding a budget, earning from work it performs and spending on work it needs.
  • Governance: Proposal voting on component inclusion, protocol fees and treasury allocation, weighted by holdings and by usage.
  • Ecosystem Listings: Exchange and aggregator listings pursued once settled usage is steady enough to stand behind.
  • Protocol Grants: Treasury funded grants for the components the registry shows people asking for and nobody has built.
